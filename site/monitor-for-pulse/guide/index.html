Part 1

Create a read-only token

About 2 minutes

A token is like a spare key that only opens the viewing room. The app uses it to read from Pulse instead of your password.

  1. Open Pulse in a browser and log in.
  2. Go to Settings, then API Access under Security.
  3. Give it a name, like my-phone, and choose only Monitoring & alerts (read).
  4. Click Generate, and copy the token right away. You may not be able to see it again.
Treat the token like a password. Don't post it in a forum, a chat or a screenshot. If it leaks or you lose your phone, delete it in Pulse and create a new one.
Part 2

Make Pulse available over HTTPS

About 30 minutes. This is the hardest part.

The app only connects over HTTPS, so your token is always encrypted. Look at the address you use for Pulse:

  • It starts with https:// and has no browser warning: you're done, so skip to Part 3.
  • It looks like http://192.168.1.50:7655: follow the steps below.

This route uses a free Cloudflare Tunnel and works from anywhere with no router changes. You need a domain name managed by Cloudflare. If you don't have one, another option is a private network such as Tailscale, which has its own HTTPS feature, but that isn't covered here.

Don't put all of Pulse directly on the internet. The steps below only expose the four read-only addresses the app needs. The Pulse website and its login page stay private. Note that Cloudflare handles the encryption, so your token and monitoring data pass through it in readable form.

A. Open a shell on a small Linux machine

Use a Debian or Ubuntu container or VM that can reach Pulse. In Proxmox, select the container and click Console. You'll also need Pulse's local address, such as 192.168.1.50.

B. Install Caddy and add this configuration

Caddy is the gatekeeper that lets only the app's requests through. Install it, then open its settings file:

sudo apt update && sudo apt install -y caddy
sudo nano /etc/caddy/Caddyfile

Add this at the bottom. Change pulse.example.com to your own address, and 192.168.1.50 to your Pulse address:

Fill in your detailsThe commands below update as you type. Nothing is sent or saved.
http://pulse.example.com:8765 {
	bind 127.0.0.1

	@apps {
		method GET
		path /api/resources /api/alerts/active /api/metrics-store/history /api/version
	}
	handle @apps {
		reverse_proxy 192.168.1.50:7655 {
			header_up -Forwarded
			header_up -X-Forwarded-Scheme
			header_up -X-Forwarded-Port
		}
	}
	handle {
		respond "Not found" 404
	}
}

Save with Ctrl+O, Enter, then Ctrl+X. Then check it and apply it:

sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile && sudo systemctl reload caddy

C. Create the tunnel

  1. In the Cloudflare Zero Trust dashboard, go to Networks → Tunnels and create a Cloudflared tunnel.
  2. Choose Debian and 64-bit. Run the commands Cloudflare shows on your Linux machine, in order, including Install as a service.
  3. Wait for the tunnel to show Connected.
  4. Add a published application route with the details below. Leave the other settings alone.
The install command contains a secret tunnel token. Don't share it or include it in a screenshot.

Part 3

Set up the iPhone app

About 2 minutes

  1. Install Monitor for Pulse from the App Store and open it.
  2. Under Your Pulse address, enter your HTTPS address.
  3. Under A read-only API token, paste the token from Part 1.
  4. Tap Connect. Your machines should appear within seconds.
What the colours mean: green is fine, orange needs a look, and red needs action soon. Tap a guest to see plain-language steps for fixing it.

Add iPhone widgets

Open the app once so the widget receives your connection. Then long-press your Home Screen, tap Edit, then Add Widget, and search for Monitor for Pulse. For the Lock Screen, long-press it and choose Customize. Widgets need iOS 17 or later, and iOS decides when they refresh, usually within about 15 minutes.

Part 4 · Optional

Add the Mac widget

About 5 minutes. Requires macOS 14 or later.

  1. Install Monitor for Pulse from the Mac App Store and open it.
  2. Enter the same address and token, then click Connect.
  3. Turn on Open at login if you want updates to continue after a restart.
  4. Right-click your desktop, choose Edit Widgets…, search for Monitor for Pulse, and drag a size onto the desktop.
The app stays in the menu bar as a small pulse-line icon, because that's what fetches the widget's data. If you quit it, the widget stops updating and shows “Offline”. macOS decides when widgets redraw, so it can lag a few minutes.
Part 5 · Optional

Show temperature

About 10 minutes

The Temp gauge only appears if Pulse has a temperature reading. That usually means installing the Pulse agent on the Proxmox host.

  1. In Pulse, go to Settings → Infrastructure, and click Install agent next to your machine.
  2. Leave Allow Pulse to run commands on this host switched off. Temperature doesn't need it.
  3. Click Generate token, then copy the Install on Linux command.
  4. In Proxmox, select your node and open Shell, then paste the command.
  5. When asked, paste the agent token. Nothing appears as you paste, which is normal.
The installer runs on your Proxmox host and comes from your Pulse server, not from this app. Follow what your version of Pulse shows if it differs from these steps.
Help

If something goes wrong

What you seeWhat to try
“has to be reached over HTTPS”Your address starts with http://. Follow Part 2.
“Can't reach Pulse”Open the same address in your device's browser. A certificate warning means your certificate isn't trusted, and no page means the address or network is the problem.
“rejected the API token”Copy the whole token again, or create a new one using Part 1.
Some information is missingCheck that all four addresses are in the Caddy step, with no typos.
Widget says “Offline”Check for the pulse-line icon in your Mac's menu bar. If it's gone, open the app again.
No temperature gaugeCheck whether Pulse itself shows one, then follow Part 5.
